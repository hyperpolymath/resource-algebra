= resource-algebra — the parametric grade algebra shared by the type family
:toc: left

== Overview

One Agda record, `ResourceAlgebra`, states what a grade algebra is for the
hyperpolymath type family: alternatives form an idempotent commutative
monoid `(⊕, 𝟘)`, sequence forms a monoid `(⊗, 𝟙)`. Optional layers add the
`⊕`-induced order and monotone sequencing (`IsOrdered`), distributivity
(`IsDioid`, which yields `IsOrdered` by a proof, not a second obligation),
and an annihilating zero (`IsAnnihilating`).

Four instances are checked against it:

[cols="1,2,2,1",options="header"]
|===
| Instance | Source of the definition | Alternatives / sequence | Status
| `Instances.Loss` | echo-types `experimental/echo-additive/Grade.agda`, transcribed | min / + on ℕ ∪ {∞} | transcribed, PROVEN
| `Instances.MaxPlus` | tropical-types `TropicalSessionTypes.lean`, transcribed | max / + on ℕ ∪ {−∞} | transcribed, PROVEN; Lean bridge OPEN
| `Instances.HWM` | occupancy-types operational model, *proposed* (its R2–R3 algebra is not yet defined) | componentwise max / peak-and-drift | DESIGNED, PROVEN against this definition
| `Instances.MinMax` | typed-wasm L11 bottleneck (`Tropical.tropMax`), which defined it locally | min / max on ℕ ∪ {∞} | PROVEN; typed-wasm adoption DESIGNED
|===

This repository is a kernel module of the family, not a family of its own.
It exists so that K-CUT-LOSS (choreographic-types) can be stated once,
parametrically, and discharged three times, instead of being proved against
a single concrete algebra that bakes in one repo's vocabulary.

`Morphism.agda` defines strict (`Hom`) and lax (`LaxHom`) maps between
instances and says which exist: `peak` is lax HWM → MaxPlus and nothing
strict leaves HWM; Loss → MaxPlus has exactly two strict maps and
MaxPlus → Loss exactly one, and none of them separates two positive
grades; the identity is lax Loss → MinMax. Transport of K-CUT-LOSS along these maps is
not proved here (link:docs/status/PROOF-STATUS.adoc[], Open).

== What is standard and what is ours

*Standard:* idempotent semirings (dioids), the max-plus and min-plus
semirings, the observation that distributivity implies monotonicity of
multiplication for the natural order.

*Ours:* the layering (what K-CUT-LOSS needs versus what K-CUT-WARRANT
needs), the three estate instances held against one record, the
high-water-mark proposal, and the checked separation witnesses
(`Separation.agda`) that turn four boundary sentences into
`refl`-plus-inequality facts: an occupancy bound is not a cost bound; echo
alternatives are min while tropical alternatives are max; the induced order
runs opposite ways in the two; a bottleneck bound is not a loss bound.

== What this is not

* Not an import of echo-types or tropical-types. The instances are
  transcriptions; the correspondence is a review obligation recorded in
  link:docs/status/PROOF-STATUS.adoc[].
* Not the K-CUT statement. Global/local types, projection and cuts live in
  choreographic-types; this repository supplies the algebra they are
  parametric in.
* Not occupancy-types' algebra. `Instances.HWM` is a proposal that the
  occupancy repo's own definition supersedes on arrival.

== Build

[source,bash]
----
just check-agda  # core proofs under --safe --without-K --double-check,
                  # then every tests/reject/*.agda must be refused at its
                  # invalid declaration
----

Builtins only (`--no-libraries`). It checks locally under Agda 2.6.3. CI
(`proofs.yml`) pins the Debian `agda-bin` 2.6.4.3 package; until 2026-10-14
that workflow called a script that does not exist, so a CI check is evidence
only from its first green run.

== AI-Assisted Installation (Recommended)

=== Just say it

Say this to any AI assistant that can read a URL and run commands (or give you
commands to paste):

[source,text]
----
Set up resource-algebra from https://github.com/hyperpolymath/resource-algebra
----

The URL is the key: it leads the assistant to
link:docs/AI_INSTALLATION_GUIDE.adoc[`docs/AI_INSTALLATION_GUIDE.adoc`], the
complete step-by-step recipe for this repository. The assistant checks your
system, installs the prerequisites, fetches and sets up resource-algebra, and
verifies it with `just doctor`.

* `./launcher.sh --ai-setup` (or `just ai-setup`) prints the line and the guide path.

=== What you will be asked

. Your operating system (Linux, macOS, or Windows via WSL2).
. Where to put it (default `~/src/resource-algebra`).
. To confirm the privacy notice below.

=== Privacy and security

[IMPORTANT]
====
Setting up resource-algebra clones this repository and installs its developer
tools per-user with mise (no administrator rights, nothing sent anywhere).
====

=== Troubleshooting

Run `just doctor`; each FAIL carries a code explained in
link:docs/SETUP.adoc#troubleshooting[`docs/SETUP.adoc` §Troubleshooting], and
`just heal` applies the automatic fixes. Prefer to do it yourself? The full
manual route is link:docs/SETUP.adoc[`docs/SETUP.adoc`]; developers and
maintainers can brief an AI with `just ai-warmup dev` / `just ai-warmup maintainer`.

== What you get

* *Machine-readable metadata* (`.machine_readable/descriptiles/`) — `STATE`, `META`,
  `ECOSYSTEM`, `PLAYBOOK`, `AGENTIC`, `NEUROSYM`, `CLADE`, and `anchors/ANCHOR`,
  in deed, so tools and agents can read the project's state and boundaries.
* *AI gatekeeper protocol* — `resource-algebra_chora.deed` (the repo deed) is the
  universal entry point that tells an AI agent how to work in this repo before it
  touches anything; it carries the AI allocation policy and the ply directory tree.
* *Typed ABI/FFI seam* — `src/interface/Abi/` (Idris2 type + layout proofs) over
  `src/interface/ffi/` (Zig implementation), with generated C headers.
* *CI/CD* — GitHub Actions for quality, security (CodeQL, Scorecard, secret
  scanning), multi-forge mirroring, and RSR anti-pattern enforcement.
* *Supply-chain & reproducibility* — container layering (stapeln), Guix shells,
  SBOM, and signing hooks.
* *Governance* — `GOVERNANCE.adoc`, `MAINTAINERS.adoc`, `.github/` community health
  files, and a release `AUDIT.adoc` gate.
