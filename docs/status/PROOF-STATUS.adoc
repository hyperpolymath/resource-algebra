== Agda leg: invocation and receipt

* *Invocation.* `scripts/check-agda.sh` runs `agda --safe --without-K
--cubical-compatible --no-libraries --ignore-interfaces --double-check
-W error -W noUnsupportedIndexedMatch -i src`, and every module also
declares `--exact-split --no-sized-types --no-guardedness` (the estate
strict flag set, from main #21) over `src/ResourceAlgebra/All.agda`, the unit tests
(`tests/unit/AllTests.agda`) and the eight expected rejections. A rejection
must fail at its invalid declaration with the message its `-- EXPECT:` line
names. A refusal with any other message fails the gate, and so does any
warning other than `UnsupportedIndexedMatch`.
* *Import cone.* Only `src/ResourceAlgebra/`: no standard library and no
other library. There is no `postulate` (refused by `--safe`), no hole and no
`TERMINATING` or similar pragma.
* *Receipt.* CI (`proofs.yml`) installs Agda 2.6.4.3, asserts the version
and checks the proofs. It then writes a receipt to the run summary with the
source commit, `agda --version`, the package version and its SHA256 from
Debian's signed index, the digest of the installed binary, the flags read
from the script, and the import cone. Installing Agda from Debian rather
than Guix is a §6 deviation, recorded in `proofs.yml`; its state is `open`.
* *History.* Until 2026-11-09 the gate ran `--safe --without-K
--no-libraries --double-check`. That profile passed in CI from 2026-10-14
(resource-algebra#4). Under §2.1 those runs are historical evidence, not
receipts for the canonical profile. On 2026-11-09, `_≤_` and the
constructor-injectivity lemmas were restated so that the core checks under
`--cubical-compatible` with no `UnsupportedIndexedMatch` warning. The
statements of the theorems below did not change.
* *Expected rejections.* Eight claims must be refused, each with the message
its `-- EXPECT:` line names. In order, those messages are:
`min m n != max m n`, `p != zero`, `suc _ != zero`, `max m n != m + n`,
`max p₁ (n₁ + p₂) != p₁ + p₂`, `3 != 5`, `inf != fin 3` and `… != bot`.
These are controls for the PROVEN rows. They are not themselves theorems.

=== Why the Rocq leg is re-proved, not transported

PROOF-POLICY §2 asks for Dedukti transport first. For this development it
is `unavailable`, for two reasons checked on 2026-11-09:

. *The translator cannot read the canonical profile.* Agda2Dedukti's last
commit (`c7c7d67`, January 2022) pins a fork of Agda 2.6.3-dev
(`Deducteam/agda@b026db1`) that has no `--cubical-compatible` option. It
builds with Stack on GHC 8.10.7, whose download host this session's network
refuses. So the translator was not run on these sources.
. *Lambdapi's Rocq export drops the computation the proofs need.* The
Agda2Dedukti encoding expresses Agda's definitional unfolding (`max`, `+`,
every instance operation) as rewrite rules. Lambdapi 4.0.0's `raw_coq`
export prints "Command not translated" for every `rule` and turns every
symbol into an `Axiom`. On a three-line probe whose proof depends on one
such rule, Rocq 9.3.0 rejects the exported definition (`"refl (s z)" has
type "P (s z)" while it is expected to have type "P (add (s z) z)"`). The
`stt_coq` export needs an encoding of simple type theory, which this is
not. Even an output that type-checked would rest on one `Axiom` per symbol,
which PROOF-POLICY §8.4 would have to list.

=== Statement correspondence

Both legs restate each Agda declaration with the same carriers, operations
and quantifiers. These differences hold for every row:

* Agda's `≡` lives in `Set`, checked `--without-K`. Rocq's and Lean's `=`
live in an impredicative `Prop`, and Lean's is proof-irrelevant. Every
statement here is an equation, an order fact or a negation, so this
changes no statement's strength.
* The law records (`IsAltMonoid`, `IsSeqMonoid`, `IsOrdered`, `IsDioid`,
`IsAnnihilating`) are `Prop` records in Rocq and Lean and `Set` records in
Agda, with the same fields. `ResourceAlgebra` itself has the same seven
fields.
* `max` and `min` are defined in both legs by the same three equations as
Agda's Prelude (`rmax`, `rmin`). The Rocq leg proves them equal to the
standard library's `Nat.max` and `Nat.min` before `lia` uses them.
`_+_` recurses on its first argument in Agda and Rocq and on its second in
Lean. It is the same function.
* HWM's bound `drift ≤ peak` is Agda's own `_≤_` and the standard `le` in
the legs. Both are the usual order on ℕ, so the carrier has the same
elements, and in all three provers two grades are equal when their peak
and drift are.

* Questions' carrier `Q n` is defined by recursion on `n` in all three
provers: Agda's `⊤` and `Σ` (both with eta), Lean's `Unit` and `Prod`, and
Rocq's `unit` and `prod`. Rocq has no definitional eta for either, so its
leg splits a grade into its bits before it computes; `zip` there takes the
two projections where Agda matches on the pair. The statements are the
same equations. Agda's `_∨_` and `_∧_` are defined by the same two
equations as Lean's `or`/`and` and Rocq's `orb`/`andb`.

== Open (not proved)

* K-CUT-LOSS itself. It is not stated here: this repository supplies the
algebra it will be parametric in. The expected shape, also `OPEN`, is that
the equality needs only the core record and the K-CUT-WARRANT bound also
needs `IsOrdered`.

say which ones exist. No theorem here states that a strict morphism
carries a cut-loss equality, or that a lax one carries a cut-loss bound.

`OPEN`.
* Morphisms into or out of MinMax, other than `loss-bottleneck`, are not
classified.
* Questions: no morphism into or out of it is classified, and it has no
unit test and no expected rejection as a control. Its ⊕ reads a grade as
"lost on every branch", which is sound only when the reader of the grade
chooses the branch (Q-4). A grade for alternatives that another party
chooses, and a grade over merged pairs (which do not compose by union),
are not stated.
* Grades for every row: a passing `proofs.yml` run on the merged commit, and
for `PWG-1` receipts kept per source commit (see Receipts).

== Discipline

Prose, citation and artefact must agree before any status moves. A status
moves only with a named declaration or a named receipt. A grade moves only
with a receipt.
