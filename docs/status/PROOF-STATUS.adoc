* *Invocation.* `scripts/check-agda.sh` runs `agda --safe --without-K
--cubical-compatible --no-libraries --ignore-interfaces --double-check
-W error -i src`, and every module also
declares `--exact-split --no-sized-types --no-guardedness` (the estate
strict flag set, from main #21) over `src/ResourceAlgebra/All.agda`, the unit tests
(`tests/unit/AllTests.agda`) and the twenty-three expected rejections. A rejection
must fail at its invalid declaration with the message its `-- EXPECT:` line
names. A refusal with any other message fails the gate, and so does any
warning, `UnsupportedIndexedMatch` included. Until 2026-11-16 the gate
suppressed that one warning; the core raised none, and
`tests/check_agda_warning_gate_test.sh` now shows the gate's flags refuse
an indexed match.
* *Import cone.* Only `src/ResourceAlgebra/`: no standard library and no
other library. There is no `postulate` (refused by `--safe`), no hole and no

The grades do not carry forward (§8.4). A later commit that changes `src/`,
a recheck leg, the gate or the checker pins needs a new receipt for the
new commit, and until then its rows fall back to the grade its receipts
support. The receipt deed is no longer written by hand. `scripts/proof-receipt.sh
--write` generates it with the estate's shared generator (standards
`scripts/proof-receipt.sh`, pinned at `f4e83044` on the standards branch
`claude/receipt-open-claims`, not yet on standards main; repin once it
lands). `scripts/proof-receipt.sh --check` regenerates it, refuses any
difference, runs the §8.5.3 git checks, checks that each current receipt
still describes the tree, and runs the pinned reader with a negative
control. The `receipt` job of `proofs.yml` runs `--check` on every commit.
Recording a new run is still a manual step (`--run-row`, then `--write`).

What this asks of a change. A pull request that changes a leg's inputs
(`src/`, a recheck file, the bridge or the tropical-types pin) makes the
`receipt` job fail, because the current receipt of that leg no longer
describes the tree. The change then marks that leg's row `superseded` in
the ledger of `scripts/proof-receipt.sh`, with its reason, and regenerates
the receipt: the rows fall to the grade the remaining receipts support,
which is what §8.4 says. After the merge, a follow-up records the main run
of the new commit and the grades return.

The Lean input set includes `scripts/check-lean-bridge.sh`, which holds the
tropical-types pin. The run summaries that hold the per-leg digests are
kept by GitHub for a limited time.

=== Why the Rocq leg is re-proved, not transported

PROOF-POLICY §2 asks for Dedukti transport first. For this development it
is `unavailable`, for two reasons checked on 2026-11-09:

. *The translator cannot read the canonical profile.* Agda2Dedukti's last
commit (`c7c7d67`, January 2022) pins a fork of Agda 2.6.3-dev
(`Deducteam/agda@b026db1`) that has no `--cubical-compatible` option. It
builds with Stack on GHC 8.10.7, whose download host this session's network
refuses. So the translator was not run on these sources.
. *Lambdapi's Rocq export drops the computation the proofs need.* The
Agda2Dedukti encoding expresses Agda's definitional unfolding (`max`, `+`,
every instance operation) as rewrite rules. Lambdapi 4.0.0's `raw_coq`
export prints "Command not translated" for every `rule` and turns every
symbol into an `Axiom`. On a three-line probe whose proof depends on one
such rule, Rocq 9.3.0 rejects the exported definition (`"refl (s z)" has
type "P (s z)" while it is expected to have type "P (add (s z) z)"`). The
`stt_coq` export needs an encoding of simple type theory, which this is
not. Even an output that type-checked would rest on one `Axiom` per symbol,
which PROOF-POLICY §8.4 would have to list.

=== Statement correspondence

Both legs restate each Agda declaration with the same carriers, operations
and quantifiers. These differences hold for every row:

* Agda's `≡` lives in `Set`, checked `--without-K`. Rocq's and Lean's `=`
live in an impredicative `Prop`, and Lean's is proof-irrelevant. Every
statement here is an equation, an order fact or a negation, so this
changes no statement's strength.
* The law records (`IsAltMonoid`, `IsSeqMonoid`, `IsOrdered`, `IsDioid`,
`IsAnnihilating`) are `Prop` records in Rocq and Lean and `Set` records in
Agda, with the same fields. `ResourceAlgebra` itself has the same seven
fields.
* `max` and `min` are defined in both legs by the same three equations as
Agda's Prelude (`rmax`, `rmin`). The Rocq leg proves them equal to the
standard library's `Nat.max` and `Nat.min` before `lia` uses them.
`_+_` recurses on its first argument in Agda and Rocq and on its second in
Lean. It is the same function.
* HWM's bound `drift ≤ peak` is Agda's own `_≤_` and the standard `le` in
the legs. Both are the usual order on ℕ, so the carrier has the same
elements, and in all three provers two grades are equal when their peak
and drift are.

* Questions' carrier `Q n` is defined by recursion on `n` in all three
provers: Agda's `⊤` and `Σ` (both with eta), Lean's `Unit` and `Prod`, and
Rocq's `unit` and `prod`. Rocq has no definitional eta for either, so its
leg splits a grade into its bits before it computes; `zip` there takes the
two projections where Agda matches on the pair. The statements are the
same equations. Agda's `_∨_` and `_∧_` are defined by the same two
equations as Lean's `or`/`and` and Rocq's `orb`/`andb`.

== Evidence ledger (Ledger.agda)

A proof ledger is a list of rows. Each row has its own evidence, the §5
token of its artefact, and the earlier rows it depends on, so no dependency
cycle can be written. The derived status of a row, `eff`, is its own
evidence in sequence (⊗ of `Evidence`) with the derived statuses of the rows
it depends on. This is README-EXPLAINME's rule that a row is only as strong
as the weakest step it depends on, as a theorem rather than a convention.
A dependency index counts into the rows after its own row. An index at or
past the number of those rows names no row, even when it is below the
ledger's length, and `eff` reads it as
`proven`. So any reader of a ledger must check each dependency against the
length of that row's tail and refuse one that fails, as an
unregistered row ID, before it derives a status. That is a precondition
every reader must enforce, not a guarantee this repository gives: no
reader exists yet (the standards ledger reader is planned), and the
theorems below hold for every ledger, dangling references included.

[cols="1,4,2,1",options="header"]
|===
| ID | Claim | Agda (§5) | pwg

| E-2
| Soundness: a row's derived status is no stronger than its own evidence,
than any row it depends on, or than the evidence of any row it reaches
through dependencies.
| `PROVEN` (`eff-≼-own`, `eff-≼-dep`, `eff-≼-reach`); controls
`tests/reject/EvidenceProvenOverTested.agda`,
`tests/reject/EvidenceArguedLinkIgnored.agda`
| ungraded

| E-3

| `PROVEN` (`eff-respects`, `eff-greatest`)

|===

derives `tested-only`. A row with no dependencies keeps its own evidence.

`IsParallel R _∥_` is a layer, like `IsDioid`: `_∥_` is a commutative
monoid on `𝟙` and distributes over ⊕, so it is monotone. Nothing in the
layer relates `_∥_` to ⊗. Two exchange laws do that, and they are stated
apart, because which one holds is a property of the resource:

* `SyncBelow`: (a ∥ b) ⊗ (c ∥ d) ≼ (a ⊗ c) ∥ (b ⊗ d). Two threads that
meet in the middle are graded at most as two threads that run free. This is
the exchange law of a concurrent semiring.
* `SyncAbove`: the reverse bound.

[cols="1,4,2,1",options="header"]
|===
| ID | Claim | Agda (§5) | pwg

| P-1
| The layer: a parallel composition has a right unit, distributes on the
right and is monotone on both sides. A dioid with a commutative ⊗ is
parallel with `_∥_` = ⊗, and then both exchange laws hold, as an equality.
| `PROVEN` (`IsParallel` with `unitʳ`, `distribʳ`, `monoˡ`, `monoʳ`;
`seq-parallel`, `seq-sync-below`, `seq-sync-above`)
| ungraded

| P-2
| Work. `Loss` and `MaxPlus` are parallel with `_∥_` = + (their ⊗), and
have both exchange laws.
| `PROVEN` (`Loss-parallel`, `Loss-sync-below`, `Loss-sync-above`,
`MaxPlus-work`, `MaxPlus-work-sync-below`, `MaxPlus-work-sync-above`)
| ungraded

| P-3
| Span. `MaxPlus` is parallel with `_∥_` = max on finite costs (`bot`
absorbs). `SyncAbove` holds: max (a + c) (b + d) ≤ max a b + max c d.
`SyncBelow` does not: 1 ∥ 0 then 0 ∥ 1 takes 2 when the threads meet in the
middle and 1 when they run free.
| `PROVEN` (`MaxPlus-span`, `MaxPlus-span-sync-above`,
`MaxPlus-span-not-sync-below`); control `tests/reject/SpanSyncBelow.agda`
| ungraded

| P-4
| Occupancy. `HWM` is parallel with `_∥_` = the sum of the peaks and the
sum of the drifts. `SyncBelow` holds. `SyncAbove` does not: two threads of
peak 1, one before the meeting and one after it, hold 1 when they meet in
the middle and are graded 2 when they run free.
| `PROVEN` (`HWM-parallel`, `HWM-sync-below`, `HWM-not-sync-above`);
control `tests/reject/HWMSyncAbove.agda`
| ungraded
|===

P-3 and P-4 together say that elapsed time and occupancy exchange in
opposite directions, so no single exchange law belongs in the layer.

== The loop grade (Star.agda)

`IsStar R star` is a layer: `star a` is the grade of "a, any number of
times". It is a fixed point of x ↦ 𝟙 ⊕ (a ⊗ x) and the least one on both
sides (Kozen's axioms for a Kleene algebra).

[cols="1,4,2,1",options="header"]

| ID | Claim | Agda (§5) | pwg

algebra, so a loop grades as `fin 0`.
| `PROVEN` (`IsStar` with `star-𝟙`, `star-step`; `unit-top-star`,
`Loss-unit-top`, `Loss-star`)
| ungraded

| K-2
| A grade whose loop equation 𝟙 ⊕ (a ⊗ s) ≡ s has no solution rules a

| `PROVEN` (`no-star`, `MaxPlus-no-fixpoint`, `MaxPlus-no-star`,
`HWM-no-fixpoint`, `HWM-no-star`); control

| ungraded

== Signed drift (Instances/SignedHWM.agda)

`HWM` records a peak and a non-negative drift, so it grades only terms that
never consume more than they allocate. `SHWM` lets the drift be any
integer, or −∞: a term may free live state it did not allocate. The peak
stays a natural, the live state above the entry level. Sequencing is HWM's
formula read in the integers: the peak of a ; b is max (peak a) (drift a +
peak b), and drifts add. `Instances.HWM` is unchanged. occupancy-types
imports it (H-2), and HWM sits inside SHWM by the maps of D-3.

The drift carrier is the max-plus dioid on ℤ ∪ {−∞} (`Drift.agda`). Its
integers are Agda's own, read as differences of naturals; every integer law
there is proved from that reading.

[cols="1,4,2,1",options="header"]
|===
| ID | Claim | Agda (§5) | pwg

| D-1
| The drift carrier (ℤ ∪ {−∞}, max, +, −∞, 0) is a `ResourceAlgebra` and
`IsDioid`. `SHWM` (peak in ℕ, drift in ℤ ∪ {−∞}, drift ≤ peak, ⊕ = max on
both, ⊗ as above, 𝟘 = (0, −∞), 𝟙 = (0, 0)) is a `ResourceAlgebra`,
`IsDioid` and `IsOrdered`.
| `PROVEN` (`Drift-RA`, `Drift-dioid`, `SHWM`, `SHWM-dioid`,
`SHWM-ordered`); control `tests/reject/SignedDriftExceedsPeak.agda` (a
drift above the peak cannot be written)
| ungraded

| D-2
| 𝟘 ≢ 𝟙: max on integer drift has no unit, so the unit of ⊕ needs drift
−∞, which no run of ⊗'s unit has. 𝟘 absorbs on the left (𝟘 ⊗ a ≡ 𝟘). On the
right it does not: a ⊗ 𝟘 keeps the peak of a, with drift −∞. So SHWM is not
annihilating.
| `PROVEN` (`SHWM-𝟘≢𝟙`, `SHWM-absorbˡ`, `SHWM-seq-𝟘`,
`SHWM-not-annihilating`); controls `tests/reject/SHWMZeroIsOne.agda`,
`tests/reject/SHWMAnnihilates.agda`
| ungraded

| D-3
| HWM sits inside SHWM. `embed` (drift read as an integer) preserves 𝟙, ⊕
and ⊗ exactly and is injective, so it is lax. It does not preserve 𝟘, and by
F-4 no strict map HWM → SHWM exists. `clampG` (a drift below zero read as
0) is lax, in the direction of F-2: the image of a sequence is below the
sequence of the images. It is a retraction of `embed` (`clampG ∘ embed` is
the identity), and it is not strict: free one cell, then allocate one, peaks
at 0, and the clamped sequence peaks at 1.
| `PROVEN` (`embed-⊗`, `embed-⊕`, `embed-lax`, `embed-injective`,
`embed-𝟘`, `no-strict-HWM→SHWM`, `clamp-embed`, `clamp-lax`,
`clamp-not-strict`); controls `tests/reject/EmbedPreservesZero.agda`,
`tests/reject/ClampIsStrict.agda`
| ungraded

| D-4
| In HWM a prefix never lowers the peak: peak b ≤ peak (a ⊗ b). With
consumption it can: free one cell, then allocate one, peaks at 0, below the
1 of the allocation alone. This is the change consumption makes.
| `PROVEN` (`HWM-prefix-keeps-peak`, `prefix-lowers-peak`); control
`tests/reject/SHWMPrefixKeepsPeak.agda`
| ungraded

| D-5
| SHWM is parallel with `_∥_` = the sum of the peaks and the sum of the
drifts. `SyncBelow` holds with signed drift: each thread stays at or below
its own peak. `SyncAbove` does not, by P-4's witness.
| `PROVEN` (`_∥s_`, `SHWM-parallel`, `SHWM-sync-below`,
`SHWM-not-sync-above`); control `tests/reject/SHWMSyncAbove.agda`
| ungraded

| D-6
| SHWM has no star: the body that allocates 1 and keeps it raises the peak
by 1 each turn, whatever the drift of the rest.
| `PROVEN` (`SHWM-no-fixpoint`, `SHWM-no-star`)
| ungraded

| D-7
| `peak : SHWM → MaxPlus` is lax, as for HWM (F-2), and agrees with HWM's
peak on `embed`.
| `PROVEN` (`speak-lax`, `speak-embed`)
| ungraded

| D-8
| On finite drift, SHWM's sequence is the bicyclic monoid. `bic` sends
(a, b) to the grade of peak a and drift a − b. It sends (0, 0) to 𝟙 and
the bicyclic product (a + (c ∸ b), d + (b ∸ c)) to ⊗, is injective, and
reaches every grade with finite drift. HWM is the part where b ≤ a, that
is drift ≥ 0: `embed` lands there, and every such pair comes from HWM.
| `PROVEN` (`bic-𝟙`, `bic-·`, `bic-injective`, `bic-onto`, `bic-HWM`,
`HWM-bic`)
| ungraded
|===

What D-1 to D-8 do not cover is under Open: the trough (option B below),
a loop grade, and adoption by occupancy-types.

== Open (not proved)

* K-CUT-LOSS itself. It is not stated here: this repository supplies the
algebra it will be parametric in. The expected shape, also `OPEN`, is that
the equality needs only the core record and the K-CUT-WARRANT bound also
needs `IsOrdered`.
* Transport of K-CUT-LOSS along a morphism. F-1..F-10 supply the maps and
say which ones exist. No theorem here states that a strict morphism
carries a cut-loss equality, or that a lax one carries a cut-loss bound.
That theorem belongs with K-CUT-LOSS in choreographic-types, and it is
`OPEN`.
* Morphisms into or out of MinMax, other than `loss-bottleneck`, are not
classified.
* Questions: strict morphisms out of one question are classified (F-8).
Morphisms out of `Questions n` for n ≥ 2, other than the projections of
F-9 and their composites with F-8, and every morphism into Questions, are
not classified. Its ⊕ reads a grade as
"lost on every branch", which is sound only when the reader of the grade
chooses the branch (Q-4). A grade for alternatives that another party
chooses, and a grade over merged pairs (which do not compose by union),
are not stated.
* Parallel composition and the loop grade for the other instances. MinMax,
Questions, Evidence and Diamond are not instantiated. `unit-top-star` and
`seq-parallel` are expected to cover those whose 𝟙 is greatest and whose ⊗
commutes; that is not checked.
* A loop grade for occupancy. HWM has no star (K-2) and no HWM with a top is
defined. It belongs with occupancy-types' own algebra (H-2).
* The trough of a signed run (option B). A term that consumes needs live
state on entry. SHWM bounds the peak above the entry level and does not
record how far below it a run goes, so it cannot say that a run never takes
the live state below zero. The proposal is a third component: the trough
t ≤ 0, the lowest level relative to entry, with t ≤ drift ≤ peak and the
trough of a ; b = min (trough a) (drift a + trough b). For a deterministic
walk, −t is the peak of the mirrored run and the triple records its prefix
extrema. The proposed alternative operation ⊕ = (max, min, max), in
(peak, trough, drift) order, forgets the smaller branch drift. It cannot
give a sound entry requirement after a suffix: choosing drift −1 or +1,
then taking a suffix with trough −2, can reach −3, while that summary
reports −1. Alternatives are therefore excluded from the entry-safety
claim; supporting them requires retaining a lower bound on branch drift
and using it in the sequence trough bound. Forgetting the trough recovers
the SHWM summary, but does not establish entry safety. For deterministic
sequences, the entry requirement −t is a typing precondition, which
belongs to occupancy-types (IS-NOT), so it is written up here and not
built. Whether to build it is an owner call.
* Signed drift in occupancy-types. That repository imports `Instances.HWM`
(H-2). Using `SHWM` there, or the trough, would be its own change, made
there.
* A loop grade for signed drift. SHWM has no star (D-6), and no SHWM with a
top is defined.
* No law here relates `star` to `_∥_`, and no morphism is shown to preserve
either. `peak-lax` is not checked against `_∥h_` and `tPar`.
* Which exchange law (P-1) a cut needs is a question for K-CUT-LOSS in
choreographic-types.
* CI that emits the receipt of each main run by itself. The check half
exists (`scripts/proof-receipt.sh --check` in the `receipt` job of
`proofs.yml`). Recording a new run is still manual: `--run-row`, then
`--write` (see Receipts).
