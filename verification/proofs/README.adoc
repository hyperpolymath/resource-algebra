= Formal Verification Proofs

Which prover carries which obligation is set estate-wide by the proof policy,
`3-practice/PROOF-POLICY.adoc` in `hyperpolymath/standards`. Read it there;
this page only maps it onto this directory.

== Which prover for which obligation

[cols="1,1,2",options="header"]
|===
|Code or obligation |Verifier |Where it lives

|Rust code
|*Creusot*
|On the Rust code itself (contracts in the crate), not in this directory.

|Ada code
|*SPARK*
|On the Ada code itself, checked by `gnatprove`.

|APIs, ABIs and engineering properties
|*Idris2*
|`idris2/` (the ABI proofs are mandatory).

|Theory
|*Agda*, rechecked in *Rocq* and *Lean*
|`agda/` is the source of truth; `coq/` and `lean4/` hold the recheck legs
(Dedukti transport first, hand re-proof as the fallback; no Mathlib).
|===

Statements about one repository's types, functions or wire formats are
engineering (Idris2). Statements that would hold for any implementation are
theory (Agda). Behaviour of first-party Rust or Ada code (pre- and
postconditions, loop invariants, absence of run-time errors) is proved with
Creusot or SPARK on that code, not restated in Idris2.

Another tool only where it is plainly the right one, recorded beside the
artefact and in `docs/status/PROOF-STATUS.adoc` (policy §4). `tlaplus/` is
such an exception: a finite model check is reported as `TESTED`, with its
bounds. For Rust, *Kani* (unsafe and FFI seams, reported `TESTED` with
bounds) and *Aeneas* (Rust that implements an Agda-proved theorem) are
standing exceptions that run alongside Creusot, never instead of it.

== Third-party code

Dependencies (crates, libraries, vendored or forked code) are not converted,
re-proved or annotated to meet this policy. Where a proof here relies on a
dependency's behaviour, state that reliance as a trusted boundary
specification and record it as `ASSUMED`, with the dependency and version,
in `docs/status/PROOF-STATUS.adoc`. When choosing between dependencies that
fit equally well, prefer one that carries its own verification. This is a
preference, not a gate.

== This repository

Every obligation here is *theory*: the resource algebra and its instances,
morphisms and separations would hold for any implementation. There is no
ABI, FFI, wire format or protocol, so there are no Idris2 or TLA+
obligations (`docs/status/PROOF-NEEDS.adoc`).

[source]
----
src/ResourceAlgebra/   # Agda: the source of truth (not proofs/agda/)
tests/unit/            # Agda: closed computations and small lemmas
tests/reject/          # Agda: claims that must be refused, with the reason
verification/proofs/
├── coq/               # Rocq recheck leg (re-proved; transport unavailable)
└── lean4/             # Lean recheck leg (re-proved; no Mathlib)
----

The template shipped example modules in this directory (`Properties.agda`,
`TypeSafety.v`, `ApiTypes.lean`, `Types.idr`, the `ABI/` modules,
`StateMachine.tla`). They were layout examples, not evidence, and were
deleted on 2026-11-09: none was a recheck of this repository's theorems, and
`ApiTypes.lean` had never compiled. Each recheck leg, its route and its
statement correspondence are recorded per theorem in
`docs/status/PROOF-STATUS.adoc`.

== Verification commands

[source,bash]
----
just proof-check-all       # Agda, Rocq and Lean legs, then the escape-hatch scan
just proof-check-agda      # scripts/check-agda.sh: the canonical §2.1 invocation
just proof-check-coq       # Rocq leg, per verification/proofs/coq/MANIFEST
just proof-check-lean4     # Lean leg, per verification/proofs/lean4/MANIFEST
----

== Banned patterns

The following MUST NOT appear in any proof file:

- `believe_me` (Idris2)
- `assert_total` (Idris2)
- `postulate` (Idris2/Agda)
- `sorry` (Lean4)
- `Admitted` (Coq)
- `unsafeCoerce` (Haskell)

CI enforces this via `panic-attack assail --proofs-only`.

== Adding new proofs

1. Classify the obligation with the table above and record it in
   `docs/status/PROOF-NEEDS.adoc`.
2. Put Rust and Ada proofs on the code; put the rest in the matching
   directory here.
3. Ensure `%default total` (Idris2) or the equivalent.
4. Run the verification command.
5. Update `docs/status/PROOF-STATUS.adoc`, including the recheck legs of any
   theory proof and any `ASSUMED` boundary specifications.
